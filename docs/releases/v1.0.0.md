First release of DocPilot: multi-tenant document Q&A with hybrid retrieval and streamed,
cited answers. It runs entirely on free, local components (no accounts, no API keys).

## Highlights

- **Upload** PDF, DOCX and Markdown, with asynchronous ingestion through Redpanda/Kafka:
  - idempotent processing, with lease-based claims and `(tenant, sha256)` de-duplication;
  - exponential backoff with full jitter, a dead-letter topic, and a per-document status API.
- **Hybrid retrieval in Postgres:**
  - pgvector HNSW and Okapi BM25 (computed in SQL over a weighted `tsvector`), fused with
    Reciprocal Rank Fusion;
  - a relevance gate, configurable top-k, and an optional local cross-encoder reranker.
- **Cited answers over SSE**, with refusal when the documents don't contain the answer:
  - the keyless built-in extractive answerer is the default;
  - Ollama is optional;
  - OpenAI and Anthropic switch on only when their key is set.
- **Multi-tenant auth:** JWT sessions and per-tenant API keys, plus a per-tenant Redis
  token-bucket rate limit (an atomic Lua script).
- **Caches:**
  - a Redis answer cache (exact and normalised question), invalidated by a per-tenant
    corpus version;
  - an in-process embedding LRU cache.
- **Observability:**
  - structured JSON logs;
  - Prometheus RED and per-stage metrics, with a provisioned Grafana dashboard;
  - OpenTelemetry traces in Jaeger, propagated through Kafka headers;
  - `/healthz` and `/readyz`.
- **React + TypeScript UI** (Vite, Tailwind), also published to GitHub Pages as a
  browser-only demo, together with the API reference.

## Measured

| | Result |
|---|---|
| Retrieval, 48 answerable questions (hybrid) | hit@5 1.000, hit@1 0.896, MRR@10 0.935 |
| BM25 vs `ts_rank` (keyword hit@1) | 0.812 vs 0.750 |
| Answers (extractive) | fact recall 0.812, 6/8 correct refusals, 0 false refusals, citation validity 1.000 |
| Query p50 / p95, 1 user (full retrieval + answer) | 38 / 59 ms |
| Query p50 / p95, 32 users on a shared 4-vCPU VM | 650 / 1,000 ms; 32.2 HTTP req/s in total, 0 failures |
| Embedding cache A/B at 32 users (p50) | 3.3 s → 0.65 s |
| Ingestion, 2 workers, mixed PDF / DOCX / Markdown | 426 documents/min, 0 failures |

Commands, raw Locust CSVs and environment details are in `benchmarks/results/`, and the
evaluation results are in `eval/results/`.

## Quality gates

- 229 tests at 95% branch coverage (CI fails below 80%).
- `mypy --strict`, ruff, and import-linter architecture contracts.
- An end-to-end smoke test of the full `docker compose` stack in CI.

## Known limitations

- The evaluation set is small (56 questions), and the extractive refusal threshold was
  tuned on it.
- The extractive answerer quotes sentences; it cannot paraphrase or combine facts. Use
  Ollama or a hosted provider for that.
- Load tests ran with everything on one 4-vCPU machine, so treat the numbers as a floor.
